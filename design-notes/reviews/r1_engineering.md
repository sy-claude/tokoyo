# r1 技術レビュー：デザインバイブル v0.1

前提は three r187（WebGLRenderer）、Vite 8、Playwright 1.65、SwiftShader、GitHub Pages。

## 総評
手触りの数値は具体的で良い。ただし次の3つが未定義で、AIの推測に任せると作り直しの原因になる。
- 時間をどの時計で数えるか
- 当たり判定と地形をどう表すか
- カメラがゲームの結果を左右すること

詳細設計の01〜11はまだ無いので、規則はbibleで先に固定する。

## 必須修正

### A1 時間の規則
**問題**：f と s が混ざっている。ヒットストップ・見切り×0.3・符×0.15 が重なったときの数え方も決まっていない。

**修正**：
- 時計は2つにする。
  - **実tick**：60Hzの固定更新の回数。一時停止で止まる。
  - **局所時間**：実tickにキャラごとの倍率を掛けたもの。
- 倍率は「世界（符の間は0.15）× 個別（見切りスロー0.3）× ヒットストップ（0）」の積で決める。
- 実tickで数えるもの：ヒットストップ、先行入力、見切りの1.5s、符の3.0s、カメラ。
- 局所時間で数えるもの：上記以外すべて（技のフレーム、無敵、予兆、状態異常、溜め、結界の回復）。
- 技は整数f、長い効果はsで書き、読み込み時にtickへ換算する。名前に単位を付ける（`startupF`、`durS`）。
- ヒットストップ式の damage は倍率を掛ける前の基礎値とする。射撃の攻撃側は止めない。

**理由**：後から直すと全タイマーの書き換えになる。符の最中に当たるとヒットストップが6.7倍に伸びる不具合も防げる。

### A2 見切りの判定が実装できない
**問題**：「重なる直前8f以内に回避開始」は、回避を始めた時点で未来の重なりを予測しないと判定できない。しかも回避で離れれば重ならないので、見切りが成立しない。

**修正**：
- 回避を始めた位置に「残像の被弾判定」を8f（易しい設定は12f）残す。残像か、無敵中の本体に敵の攻撃判定が触れたら成立とする。
- 同じ攻撃で2度成立しないよう、攻撃ごとに `attackInstanceId` を振る。
- 弾と衝撃波も対象にする。
- 「周囲」の範囲を数値で決める（仮に12m、その敵の弾も含む）。

### A3 カメラはシミュレーション側に置く
**問題**：次の処理はどれもカメラの状態で結果が変わる。
- カメラ基準の移動
- ソフトロックの「カメラ方向」
- 滅の「画面内」
- ロック解除の「見えない」
- 敵をタップしてロック
- 画面外の矢印

**修正**：
- カメラの状態は固定更新の中で決定的に更新し、描画側は補間するだけにする。
- 画面に関わる判定は、シミュレーション（以下シム）側のカメラと、入力に含めた画面サイズで計算する。
- 戦闘カメラは10m以内で入り、14m超が1s続いたら出る（ヒステリシスで行ったり来たりを防ぐ）。

### A4 当たり判定と地形（外部物理なし）
- **地形**：0.5m間隔の高さ格子（双一次補間）と、格子ごとの面種別（地面・崖・海・禁止）で表す。
- **静的な障害物**：鉛直の円柱、向き付きの箱、球の3種類だけ。上に乗れるかどうかの印を付け、4mの一様グリッドで検索する。
- **キャラの移動**：キャラは鉛直カプセル。次の順で処理する。
  1. 水平に動かす
  2. 障害物から押し出す（2〜3回繰り返す）
  3. 接地させる（段差0.4m以下は登る。45°を超える斜面は壁として扱う）
- **攻撃判定**：技データ側の球・カプセル（キャラ原点基準、フレーム範囲付き）と、被弾カプセルを比べる。弾は移動量ぶんの球と、格子を刻んで進むレイで判定する。
- **カメラの障害物判定**：同じ衝突世界の中で、半径0.25mの球を刻んで進める。描画メッシュとRaycasterは使わない。
- **海**：足が水面より0.3m下に入ったら落下扱いにする。
  - 安全地点は0.5sごとに記録する。記録するのは、接地していて崖の縁から1.5m以上離れた位置だけ。
  - 復帰後は1s無敵にする（仕様に無いので追加）。
- **唯一の元データ**：小道具の定義に見た目と当たり判定の両方を持たせる。地形も、同じ生成関数とシードから描画用とシム用を作る。

### A5 キャラのリグ
**問題**：部品ごとに別メッシュにすると、輪郭で描画が倍になる。12部品×敵10体で240命令になり、予算100を超える。

**修正**：
- 部品は1キャラ＝1つの**SkinnedMesh**に結合する（各頂点を1本の骨に重み1で付ける「剛体スキン」）。輪郭も含めて1体2命令で済む。
- ポーズは「技データに置く関節のキーフレーム」＋「手続きで足す層（呼吸・伸縮・足の接地）」の純関数にする。
- **攻撃判定は骨に依存させない。**
- 平らな面の岩には「輪郭用の平均法線」を別の属性として持たせ、輪郭の割れを防ぐ。

### A6 入力層
- 画面全体を覆う入力層を1枚置き、すべての指をそこで受ける。ボタンの当たりは配置の数値設定で判定する。DOMのHUDは見た目だけにする（`pointer-events:none`）。テストも同じ設定から座標を出せる。
- 入力は毎tick `InputFrame` に変換する。押下は保持しておき、1描画で複数tick進んでも最初のtickで1回だけ渡す。
- キーボード・タッチ・テスト・リプレイは同じ形式を出力する。
- 五芒星は入力側の純関数で「辺の列」に変換してからシムへ渡す。

### A7 推測で埋めることになる穴
1. **防御不能**：本作にガードは無い。意味を定義する。
2. **白雪**：
   - 蹴りがいつ出るのか（距離で切り替えると原則1.1に反する）。
   - 空中で回避ボタンを押したときの動作。
   - 黄の穢石に届くか。
3. **符**：
   - 星の隣ではない点に触れたら、無視するのか、現在点を移すのか。
   - 同じ辺をもう一度なぞった場合。
   - 指を離した後の猶予（調査では0.4s、bibleでは即発動）。
   - 符の構え中に移動できるか。
   - 醒の重ね掛け。
   - 札4枚の岩丈は醒を使えない。これは意図どおりか。
4. **奥義**：
   - 溜めをどの時点から数えるか。
   - 被弾で溜めが中断されるか。
   - 空中で溜められるか。
   - PCでの取消操作。
5. **結界**：
   - 回復は1回分ずつ順番か、並行か。
   - 罠を同時に置ける数。
   - 多段攻撃で残り時間を何回減らすか。
6. **穢域**：
   - 浄の符以外でも祓えるか。
   - 大きさと広がり方。
   - 感染の「2秒」は連続か累積か。
7. **攻撃権**：ボスや射撃型も対象に含むか。
   - さらに次の数値がすべて未定義。各マイルストーン（以下M）の文書に表で書く。
     - 敵のHPと技
     - 崩しの蓄積量
     - 全キャラの技表（奥義9種を含む）
8. **魂片**：拾った時点で保存するのか、結果画面で保存するのか。再挑戦で穢石が復活するなら、何度も稼げてしまう。
9. **ステップ**：「後方」はキャラ基準かカメラ基準か。ハードロック中はどうするか。
10. **画面**：
    - 縦向きにされたときの扱い。
    - iOSのアドレスバーで高さが変わるときの「画面高さ42%」の基準。
    - ノッチなどを避ける余白（safe-area）の扱い。
11. **単位**：px＝CSS px、角度＝度、距離＝m、と冒頭で宣言する。

### A8 保存データ
- GitHub Pagesのプロジェクトサイトは、同じ持ち主の全リポジトリとoriginを共有する。そのためlocalStorageも共有になる。
- キーには名前空間を付け（例：`tokoyo:save`）、版番号（`{v:1}`）と移行関数をM0で用意する。

## 推奨

### B1 描画予算
試算（品質「高」）では約85命令で、100以内に収まる見込み。

| 対象 | 命令数 |
|---|---|
| 地形 | 6 |
| 空・遠景の山・海 | 5 |
| 区画ごとに結合した静的物（＋輪郭） | 10＋10 |
| インスタンス描画の5種（＋輪郭） | 6＋6 |
| キャラ・敵10体・ボス | 24 |
| 結界・軌跡・粒子・影 | 6 |

この数字が成り立つ条件は次のとおり。
- **輪郭はキャラ・大きな小道具・目印だけ**に付ける。地形は輪郭なしにし、シェーダーで縁を暗くして代わりにする。
- **穢域・龍穴・丸影は地形シェーダー内の円の配列（最大16個）で描く。** 半透明の貼り絵を重ねない（重ね塗りで重くなるため）。
- 加算の粒子と結界は、カメラが近いほど薄くする。
- 文字は起動時に1回だけCanvasのまとめ画像（アトラス）に描く。ダメージ数字はDOMを使い回す。
- `antialias` はレンダラー作成時にしか指定できないので、falseに固定してDPRで画質を調整する。
- 色は必ず `THREE.Color` を通す。頂点色を直接書くと、色管理とずれて色が淡くなる。
- 起動時に `renderer.compile` を呼び、初回表示時のカクつきを防ぐ。

**品質段階**

| 段階 | DPR | 静的物の輪郭 | 粒子 | その他 |
|---|---|---|---|---|
| 高 | 1.5 | あり | 1500 | — |
| 中 | 1.25 | 目印のみ | 800 | — |
| 低 | 1.0 | なし | 500 | 霧と描画距離を縮める |

2sの中央値が18msを超えたら1段下げる。自動では上げない（上げ下げを繰り返さないため）。

### B2 敵の移動
- ナビメッシュ（移動可能範囲の網）は作らない。
- 高さ格子から「歩ける1m格子」を作る（約1.5万マス）。
- 0.5sごとにプレイヤーからの距離地図を幅優先探索で作り、敵はその勾配を下って近づく。これに敵同士の分離と回り込みを加える。
- 各敵は自分の区画から20m以上は追わない。
- プレイヤーが高台にいて届かないときは、近接の敵は威嚇し、射撃型は撃つ。灯魂は浮いているので格子を無視する。

### B3 その他
- `src/data` はJSDoc付きのJSモジュールで書き、検証関数を起動時とテストの両方で走らせる。
- `?debug=1` でconfigのスライダーと「JSONをコピー」を出す。依頼者は実機で調整した値を返すだけで済む。

## 推奨アーキテクチャ
```
src/ main.js(固定60Hz・最大5tick/描画・補間)
  core/   time rng events math save
  input/  pointerRouter layout inputFrame keyboard pentagram
  sim/    world fsm/ player enemyAI/ combat/ collision/ nav/ camera lockon stageLogic
  render/ renderer quality materials/ rig/ stage/ vfx/ cameraView
  ui/ audio/ config/ data/(characters moves enemies stages) debug/(window.__game, panel)
tests/ unit/ e2e/ replays/
```
- `sim/` と `core/` ではDOM・音・`Math.random`・`Date.now`・`performance.now` を使わない。threeは数学クラスだけ使ってよい。守られているかはgrepのテストで確かめる。
- シムが出すのは状態とイベントだけで、描画と音はそれを購読する。

```js
/** @typedef {{id:string, startupF:number, activeF:number, recoveryF:number,
 *  cancels:{into:string[],fromF:number}[], hitboxes:{fromF:number,toF:number,
 *  shape:'sphere'|'capsule',a:V3,b?:V3,r:number}[], motion:{f:number,fwd:number}[],
 *  damage:number, hitstopF?:number, knockback:{h:number,v:number}, breakDmg:number,
 *  armorF?:[number,number], invulnF?:[number,number], pose:{f:number,joints:Record<string,V3>}[]}} MoveDef */
/** @typedef {{tick:number, stick:[number,number], cam:[number,number],
 *  btn:Record<string,{down:boolean,pressed:boolean,released:boolean}>,
 *  taps:[number,number][], fu:{edges:[Elem,Elem][],released:boolean}|null, viewPx:[number,number]}} InputFrame */
```
- CharacterDef：element、hp、capsule、moveset、fuMax、hasKekkai、hasAirDash、rig.parts
- EnemyDef：element、hp、ai種別、attacks（move、telegraphF、kind、glyph、tokenCost）
- StageDef：seed、sizeM、cellM、terrain、seaLevelM、props、spawns、eseki、eiki、ryuketsu、bossGate

## M0で固定すべき不変条件
1. 60Hzの固定更新で、tickは整数。結果は毎回同じになる（シード付き乱数、ID順に更新、時刻APIは使わない）。
2. 時計は2つで、倍率は掛け算で重ねる。
3. カメラはシム側に置く。
4. シムへの入力はInputFrameだけ。リプレイはInputFrameの列で表す。
5. シムは描画・DOM・音を知らない。
6. 衝突と見た目は同じステージデータから作る。攻撃判定は骨に依存しない。
7. キャラは剛体スキンのメッシュ1つ。ポーズは純関数で作る。
8. 数値はconfigとdataにだけ書き、名前に単位を付ける。
9. 保存データには名前空間・版番号・移行関数を持たせる。
10. 描画命令は110以下。テストで検査する。
11. 色は`THREE.Color`を通す。依存パッケージは版を完全に固定する。

## 自動検証
**Node（描画なし）**：
- 跳躍の頂点が2.4±0.05m
- ステップの移動4m、無敵2〜14f
- ヒットストップの式と、複数ヒット時の割引
- 時間の重なり：符の最中でも、停止は実tickで14fを超えない
- 見切りの境界：7f・8fは成立、9fは不成立
- ダメージ計算
- 五芒星の判定
- 保存データの移行
- リプレイのハッシュ一致。意図して挙動を変えたときは `replays:update` で記録し直す。

**Playwright**：
- 844×390、タッチ有効、DPR2 の設定で動かす。
- `?test=1&seed=1` を付けると自動ループが止まり、`__game.step(n)` と `render()` で進める。速く、毎回同じ結果になる。
- 複数の指を同時に使う操作は、CDPの `Input.dispatchTouchEvent` で再現する。

**テストシナリオの例**：
- 起動から戦闘まで、コンソールエラーが0件
- スティックで走ると速度が6.5±0.2
- 攻撃を3回タップすると3段目が出る
- 奥義を1.3s押すと2段目になり、勾玉が2減る
- 木→土→水となぞると浄が出て、札が2減る
- pointercancelでスティックが離れる
- 縦向きにすると案内が出る
- 海に落ちると安全地点に戻り、HPが8%減る
- 3つの視点で描画予算を超えない

**スクリーンショット**：
- 決まった地点で撮る。AIは4×2の縮小一覧1枚だけを見て判断する（トークン節約）。
- 合否は画像ではなくシムの状態で判定する。
- 起動引数に `--enable-unsafe-swiftshader` を付ける。FPSは測らない。

## Claude Code on the web の運用
- **CLAUDE.md**：短く保つ。コマンド、不変条件、禁止事項、Mごとの読む文書の索引を書く。
- **PROGRESS.md**：現在のM、済んだこと、次の作業、既知の問題、依頼者に聞くことを書く。
- **セッションの終わり方**：毎回「verify → PROGRESS更新 → push → PR」で終える。
  - PRは1Mにつき1本。
  - ブランチ名は `m2-movement` のようにする。
  - PRの説明に「依頼者が試すこと」を3行で書く。
- **verifyの2段構成**：`verify:fast`（型検査・単体テスト・ビルド）と、e2eを含む `verify` に分ける。
- **ネットワーク**：Custom設定で、Playwrightのブラウザ配布ホストを許可する。ホスト名は初回インストールのログで確かめる。
- **setupスクリプト**：`npm ci && npx playwright install --with-deps chromium` を実行する。ブラウザの取得に失敗しても `verify:fast` は動くようにしておく。
