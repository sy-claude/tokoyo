# レビュー r1：モバイル操作・UI（対象：00_design_bible.md v0.1 の4・5・7・14章）

**座標系**：844×390 CSS px、原点は左上、(x,y)はボタンの中心。iPhone 12〜15の横画面では、左右の安全余白（safe-area）が47px、下が21px。Safariのツールバーが出ていると、高さは約330〜350pxに縮む（実測で確定すること）。物理寸法は1px≈0.166mm。

**総評**：左のスティック、右の扇形に並ぶ6ボタン、ソフトロックという骨格は定石どおりで、物理的にも収まる。ただし次の5点は実機で破綻する。
1. ロックボタンが右上にあり、親指が届かない
2. ボタン判定の拡張（＋8px）と間隔（12px）が矛盾する
3. 五芒星の点の判定半径48pxでは、隣の点を誤って捕まえる
4. 奥義の溜め中に逃げる手段がない
5. ブラウザの「戻る」と画面の向きロックへの対策がない

---
## A. 必須修正

**A1 配置は右下基準の固定pxにする**
- 問題：座標が書かれていない。iOS Safariではアドレスバーの出入りで高さが40〜60px変わるため、画面の上端基準や画面比率で置いたボタンは位置がずれる。
- 修正：
  - `viewport-fit=cover` を指定し、すべての操作部品を `env(safe-area-inset-*)` の内側に置く。
  - 位置は画面の右下（スティックは左下）からのずらし量で決める（末尾の図を参照）。
  - `visualViewport` の `resize` を受けたら配置し直す。`100vh` は使わない。配置し直しても、押下中の指の役割は保持する。
  - 最小の高さ320pxで重なりがないことを確認済み。
  - 端末差の吸収は、ボタンの直径に `clamp(H/390,0.85,1.1)` を掛けるだけにする。
- 理由：親指が届く範囲は、画面高ではなく端末の角で決まる。

**A2 判定を重ねず、回避を大きくする**
- 問題：
  - 間隔12px＋判定の拡張8px×2で、隣同士の判定が4px重なる。
  - 見切り（8f）の主役である回避が、跳躍と同じ62pxしかない。
- 修正：
  - 見た目の間隔を16px以上にする。それでも判定が重なる位置は、「距離÷半径」が最小のボタンに割り当てる。
  - 直径（判定）：攻撃80（96）、**回避68（84）**、跳躍60（76）、奥義・結界・符56（68）、注目48（60）、一時停止40（48）。
  - 攻撃の判定は、画面右下の角まで扇形に広げる。

**A3 ロックは「注目」ボタンにして跳躍の上へ移す**
- 問題：右上は右下の角から約61mm離れており、持ち替えないと押せない。
- 修正：
  - (772,150)、Ø48に置く。角から約42mm。
  - 動作：敵がいればロック、ロック中なら解除、敵がいなければ0.25秒でカメラを背後に戻す。
  - 右上には一時停止だけを残す。
- 理由：注目と視点リセットを一つのボタンにまとめる型は定着しており、原則1（一つの操作に一つの意味）にも反しない。

**A4 五芒星の誤認識をなくす**
- 問題：
  - 大きさが画面高の42%なので、Safariの高さ340pxでは143pxまで縮む。
  - 外接円の半径R=82のとき、星の辺（i→i+2）は外周上の隣の点i+1から約57pxしか離れない。判定半径48だと余裕は9px。親指の描く線が少し外へ膨らむだけで、i+1を捕まえて外周の線になる。
- 修正：
  - 星を固定pxにする。**R=84、中心は(644,226)（右から200・下から164）**。各点は木(644,142)・火(724,200)・土(693,294)・金(595,294)・水(564,200)で、どれも右下の角から29〜56mmに収まる。
  - **今いる点から捕まえられるのは、相剋の線でつながる2点だけ**にする。外周の隣の点は捕まえる対象にしない。
  - 判定半径は、始点44px、2点目以降40px。加えて、60px以内まで近づき、指の進む向きがその点から±25°以内なら吸着させる。
  - 符ボタンを押した指では描き始められず、新しく置いた指で描く。
  - 時間：構えてから最初に触れるまでの待ちは1.5秒（触れなければ消費なしで取り消し）。描き始めてからの制限は3.0秒。指を離しても0.25秒以内なら続けて描ける。5画そろったら即座に発動する。
  - 左利き設定では、星の位置だけを左へ移す。点の並び順は反転しない。
- 理由：
  - 外周の線はもともと無効なので、捕まえる候補から外すのが最も確実である。
  - 5画の道のりは約800px（13cm）あり、鋭い折り返しが4回ある。構えに入る時間まで込みで3秒は、初見には厳しい。
  - 時間切れになっても4画の「滅」が出る、段階的に弱まる設計は良い。

**A5 奥義の溜め中に逃げられるようにする**
- 問題：
  - 溜め中は無敵がない。逃げるために回避しようと指を離すと、技が出て勾玉を消費してしまう。
  - 取消条件の「70px」がどこからの距離か書かれていない。
  - 押してから0.35秒まで何も表示されないので、壊れているように見える。
- 修正：
  - 奥義(562,310)を回避(645,296)の84px隣に置く。**溜め中に指を回避ボタンへ滑らせたら、取消（消費なし）して回避する。**
  - 取消は押した点から72px以上離れたときに成立し、灰色の輪と×を出す。56px以内に戻れば溜めを再開する。
  - 輪は押した瞬間から表示する。0.6秒未満で離したら「長押し」と表示する。
  - 勾玉が足りない段は、目盛りを灰色にする。
  - 溜め時間は実時間で数え、ヒットストップや減速で止めない。
- 理由：溜めを捨てて避ける判断こそが、原則2（深さはタイミングで出す）の核心である。

**A6 ロック中の横ドラッグを切り分ける**
- 問題：
  - ゆっくり横を見たいだけでも標的が切り替わってしまう。
  - ボスが1体だけのときは横ドラッグが何も起こさず、カメラが固まったように感じる。
  - 攻撃ボタンを押し損じた指が、敵へのロックとして拾われる。
- 修正：
  - 標的の切替は**はじき操作だけ**にする。条件は、180ms以内に横へ40px以上動き、横の移動量が縦の2倍以上。1回のドラッグで切り替わるのは1回まで。
  - ゆっくりした横ドラッグは、注視の向きを±35°までずらす操作にする。指を離すと0.5秒で戻る。縦ドラッグは常に上下の角度を変える。
  - タップでのロックは、次の条件をすべて満たすときだけにする：移動12px未満、250ms未満、敵の外枠＋20px以内、どのボタンの判定からも24px以上離れている。何もない所のタップは無視する。

**A7 ブラウザの横取り対策**
- 問題：次の対策が設計に書かれていない。
  - 端からのスワイプで「戻る」が働き、ページを離れる（iOS Safari、Androidのジェスチャーナビ）。
  - 縦向きロックがオンだと、横にしても画面が回らない。
  - 長押しメニュー、ダブルタップやピンチでの拡大。
  - 音声の「中断」状態。
  - Safariは7日間操作がないとlocalStorageを消す。ホーム画面に追加した版とは保存領域が別になる。
- 修正：
  - CSS：`overscroll-behavior:none`、`touch-action:none`、`user-select:none`、`-webkit-touch-callout:none`、`-webkit-tap-highlight-color:transparent`。
  - JS：`contextmenu`・`selectstart`・`gesturestart` で `preventDefault` する。
  - 戻る（Android）：番兵として `pushState` を積み、`popstate` を受けたら一時停止にする。「もう一度戻ると終了」と表示する。
  - 戻る（iOS）：止める手段がない。区画ごとの自動保存と `pagehide` での保存を行い、`pageshow` の persisted で戻ってきたら一時停止にする。スティックの出現範囲は左端から24px以上内側にする。
  - 縦向きのとき：回転を促す画面に「縦向きロック中ならコントロールセンターで解除」と明記する。
  - 全画面（Android）：最初のタップで `requestFullscreen` と `screen.orientation.lock('landscape')` を呼ぶ。
  - 音：`pointerup` で `resume` する。中断（interrupted）状態は、次のタップで自動的に復帰させる。`navigator.audioSession.type='playback'` を使い、使えなければ無音の `<audio>` を再生し続ける方法に切り替える（どちらも実機で確認）。
  - 保存：`navigator.storage.persist()` を呼び、引き継ぎ文字列（JSONのコピー）を用意する。

## B. 推奨

**B1 HUDは見る場所に置く**
- 札・勾玉・結界の残数は**ボタン上**に表示する（結界は3つの弧と回復の扇、奥義は勾玉の数と届く段、符は「札8」）。左上はHPと状態表示だけにする。
- ボスの名前とHP（x262〜582、y6〜32）と崩しゲージ（y35〜40）は、ボス戦の間、方位帯と入れ替えて表示する。
- 画面外の敵の予兆は、画面の端ではなく**自キャラの周り、半径90pxの円の上**に出す。画面の端だと右下は親指で隠れる。
- 文字は明朝の太字で12px以上、数字は14px以上にする。

**B2 同時に使う指は2本までと明記する**
- 指の数：移動＋攻撃は2本、移動＋奥義の溜めは2本、符は右手1本（左手は離してもよい）。
- 右の親指がよく届く範囲はボタンで埋まっていて、カメラを動かせる空き領域はx338〜560と遠い。そこで、**攻撃ボタンを押したまま28px以上動かすとカメラが回る**ようにする（感度0.8倍、初期値はオン、設定で切れる）。攻撃は押した時点で出ているので、操作の意味は増えない。
- 3本指を前提にしない。iOSの3本指ジェスチャーと衝突するおそれがある。

**B3 スティック**
- 指が84px（半径の1.4倍）を超えて離れたら、台座が指を追いかけるようにする。
- 出現範囲はx24〜338、y64〜369。
- 台座の表示は画面内に収めるが、入力の原点は指が触れた点のままにする。

**B4 カメラと酔い**
- 自動回り込みの速さは「75°/秒×スティックの横成分」にする。カメラ側へ向かって走るとき（正面から120°超）とハードロック中は回り込まない。
- 戦闘距離は、敵が10m以内で入り、14m超が2秒続いたら出る。
- 千本鳥居の柱のような細い物（半径0.4m未満）は、カメラの当たり判定から外して透かす。外さないと、カメラが寄ったり戻ったりを繰り返してちらつく。
- 縦横比2.16の画面で縦の視野角60°にすると、横は103°になり広すぎる。**縦55°（横97°）を既定**にし、横が90〜100°に収まるよう縦横比から決める。
- 感度の初期値は横0.30°/px、縦0.18°/px。設定は0.5〜2.0倍、上下反転、上下の角度は−30〜+60°の範囲に制限する。
- `prefers-reduced-motion` がオンなら、画面揺れを30%、自動回り込みを「弱」にする。

**B5 タッチの遅延を見切りの判定で補う**
押したイベントの `timeStamp` で判定し、受付は10f（易しい設定は13f）を基準にする。ブラウザのタッチは60〜100ms遅れるため、8fのままでは実質半分ほどしか受け付けない。

**B6 初回起動の流れ**
1. 縦向きなら、回転を促す画面を出す。
2. タイトルに「**音を出して遊ぶ／音なしで遊ぶ**」の2つのボタンを置く。この1回のタップで、音の起動、全画面化（Android）、画面消灯の防止（Wake Lock）をまとめて行う。音なしを選んだら、鈴の音などを光の演出で補う。
3. 最初の区画を抜けた後に1度だけ、ホーム画面への追加を案内する。iOSは図で、Androidは `beforeinstallprompt` で。案内では「全画面になり、戻るの誤動作が消える。進行は引き継ぎ文字列で移す」ことを伝える。

**B7 チュートリアルとボタンの文字**
- 浜の参道で、操作を1つずつ教える。プレイヤーが実際に操作するまで次へ進まない。順番は次のとおり。
  1. 移動
  2. カメラ
  3. 攻撃
  4. 回避：最初の予兆で時間を×0.2にし、「今、避」と表示する。
  5. 跳躍・神通足
  6. 結界→奥義（封破）
  7. 符：初回は時間を完全に止め、筆でなぞる手本を見せる。最初の穢域で2画の「浄」を教える。
  8. 注目：最初の大型の敵で教える。
- 教える最中は、対象のボタンを光らせ、手の動きの見本を重ねる。
- ボタンの中に文字を入れる：攻（白雪は射）、避（空中では「神通」に変わり色も変える。使えないキャラでは灰色）、跳、奥義、結界、符、注目。

**B8 設定項目を追記する**
- ボタン配置の編集（70〜150%の拡縮、透明度20〜100%）と初期化
- 左利き用の左右反転
- スティックの方式と大きさ
- カメラ（B4の各項目）
- ロック対象の優先度
- 奥義の入力方式：「長押し」か「タップで溜め、再タップで発動」か
- 符の描き方（**初回の既定は「補助」**）
- 画面揺れ 0〜100%
- 振動（Androidのみ）

## C. 任意
- 縦向きロックを解除できない人向けの疑似横画面モード（CSSで90°回転させ、タッチ座標も変換する）
- 振動：Androidは点を捕まえたときに10ms、見切りで[20,30,20]。iOSはスイッチ要素を使う裏技を、設定でオンにした場合だけ使う。
- 符ボタンを押したまま星へ滑らせて描き始める「速描き」（上級者向けの設定）
- 低電力モード（30fps）を検知したら、画質を下げることを提案する。
- ジャイロ照準を、符を描く間と弓の照準の補助に限って使う。
