# 11 外部素材（3Dモデル・質感画像）— 依頼者の決定 U8（11/14）

> **この文書でできること**
> - キャラ・敵・ボスは、依頼者がAI（Gemini/GPTの設定画 → Meshy 等で3D化）で作った **GLB の3Dモデル** を使う。
> - 地形・岩・木・紙・墨の筆致などの **質感（テクスチャ）** は、依頼者が Gemini/GPT で作った画像を使う。
> - 動き・エフェクト・地形の形・UI の仕組みは、これまでどおりコードで作る。**素材が届いていなくても、コードの仮の見た目で必ず動く**（差し替え式）。
>
> **関連文書**：00_core（不変条件6・11の改訂）、07_art（§14 で §6 を置き換え）、03_combat（§14 アニメの対応）、09_tech（§13 取り込みの技術）、10_milestones（A1）。
> **優先**：外部素材に関することは、この文書が 07 §6・09 の該当節より優先する。

---

## 1. 方針

1. **形と描き込みは素材、手触りはコード**：見た目の密度（形・質感・顔・服）は素材で上げ、動きのタイミング・当たり判定・演出はコードとデータで決める（当たり判定は骨に依存しない：不変条件5のまま）。
2. **画風は描画側でそろえる**：素材の色はそのまま使うが、陰影は 07 §3.3 のトゥーン（3段）、輪郭は 07 §4、仕上げは紙墨パス（07 §3.7）をすべての素材にかける。PBR（金属・粗さ）は使わない。
3. **差し替え式**：素材は `data/assets.js`（素材の目録）に登録した ID で参照する。ファイルが無い・読めない・検査に落ちた場合は、**コードで作る仮の見た目に自動で戻る**（楓真は M1a の剛体スキン、その他は簡単な形）。コンソールエラーにはしない（警告1回）。
4. **元のファイルと配る用を分ける**：依頼者が置く元ファイルは `assets-raw/`（配信しない）。AI が最適化して `public/assets/` に置く（配信する）。
5. **重さの上限を守る**（§5）。超える素材は AI が軽くする。軽くできなければ、PROGRESS.md の「依頼者に聞くこと」に、依頼者にやってほしい作り直し（例：面の数を減らして書き出し直す）を書く。

## 3. 動き（アニメーションクリップ）と技の対応

### 3.1 人型セット（楓真・白雪・岩丈で共通の名前。Meshy 等の動きの一覧から近いものを選ぶ）
| クリップ名（ファイル内の名前は自由。AI が目録で対応づける） | 用途 |
|---|---|
| `idle` 待機 | 待機 |
| `walk` 歩き / `run` 走り | 移動（速さに合わせて再生速度を変える） |
| `jump` 跳躍（上昇・落下・着地を含むもの、または別々） | 跳躍 |
| `dodge` 回避（横・後ろのステップ、または前転） | ステップ・神通足 |
| `hit` 被弾（軽い怯み） / `knockdown` 倒れる / `getup` 起き上がり | 被弾 |
| `death` 倒れる（最後） | 死亡 |
| `attack1`〜`attack3` 斬りかかる・切り返す・大振り（白雪は弓を射る、岩丈は槌） | 地上3段 |
| `heavy` 大きく振りかぶる一撃 | 奥義の発動、走り攻撃 |
| `charge` 力を溜める構え | 奥義の溜め・結界 |
| `cast` 術を放つ・印を結ぶ | 符の構え・発動 |
- 全部そろわなくてもよい。**無い動きは、近いクリップ＋コードのポーズ（07 §6.7 の方式を骨の対応表で当てる）で補う**。最低限の必須は `idle`・`run`・`attack1`。

### 3.2 技との合わせ方（03 §14）
- 技のフレームデータ（03）が正本。クリップは技の長さに**伸縮**して合わせる：`MoveDef.anim = {clip, fromS, toS, hitS}`。`hitS`（クリップの中で刃が当たって見える瞬間）を技の最初の判定フレームに合わせ、前後を別々に伸縮する。
- `anim` が無い技は、`pose`（07 §6.7）で動かす。両方あるときは `anim` を使い、`pose` は上に重ねる補正として使う。

## 4. 目録（`src/data/assets.js`）と型（09 §13 と共通）
```js
/** @typedef {{id:string, kind:'model'|'texture', url:string, required:false,
 *  heightM?:number, yawDeg?:number, footOffsetM?:number,
 *  boneMap?:Record<string,string>,   // 07 §6.3 の骨名 → ファイル内の骨名
 *  clips?:Record<string,{name:string, loop:boolean, hitS?:number}>,
 *  attach?:{toAsset:string, bone:string, posM:[number,number,number], rotDeg:[number,number,number]},
 *  tintByElement?:boolean, fallback:'procedural'|'none'}} AssetDef */
```
- `heightM`：読み込み後に全体をこの身長に拡大縮小（楓真1.72、白雪1.58、岩丈1.95、面鬼2.6、穢狗の肩高0.6 など 07 §6.4 の寸法）。
- `boneMap`：取り込み時に AI がファイル内の骨名を調べて書く。人型の自動リグ（Mixamo 風の名前など）には共通の対応表を作って使い回す。
- 目録は起動時に検証する（URL・骨名・クリップ名の存在）。

## 5. 重さの上限（スマホ 60fps のため）
| 対象 | 三角形 | 質感画像 | ファイル（最適化後） |
|---|---|---|---|
| 祓人1体（武器を除く） | ≤ 12,000 | 1枚 1024²（色のみ） | ≤ 2.0 MB |
| 武器 | ≤ 2,000 | 512² | ≤ 0.4 MB |
| 小型の敵1体 | ≤ 6,000 | 512² | ≤ 1.0 MB |
| 面鬼・鬼面 | ≤ 12,000（合計） | 1024² | ≤ 2.0 MB |
| 石凝神（全部品の合計） | ≤ 25,000 | 1024²×2 まで | ≤ 4.0 MB |
| 小道具1種 | ≤ 3,000 | 512² | ≤ 0.6 MB |
| 地形・環境の質感 | — | 1024²（WebP） | 各 ≤ 0.4 MB |
| **全体** | 画面内の三角形は 07 §10 の上限（≤200,000）のまま | GPU メモリ合計 ≤ 64 MB | 初回読み込み合計 ≤ 25 MB |
- **1体＝1メッシュ＋1素材**（描画命令は輪郭込みで2のまま）。ファイルに複数のメッシュ・素材があれば、取り込み時に1つに統合する。統合できなければ PROGRESS に記録。
- 法線・金属・粗さの画像は使わない（色の画像だけ）。

## 6. 取り込みの手順（AI が行う。09 §13）
1. 依頼者が `assets-raw/models/<ID>.glb`・`assets-raw/textures/<ID>.png` 等を置く（GitHub の画面からアップロード、またはチャットに添付して設計担当が置く）。
2. AI が `npm run assets:check` で中身を調べる（三角形・骨・クリップ・画像の大きさ・ファイルの大きさ）→ 上限を超えるなら軽くする（面の削減・画像の縮小・WebP 化）。変換には `npx` で一時的に使う道具を使ってよい（**package.json の依存には足さない**。使った道具と版を PROGRESS に記録）。
3. `public/assets/models/<ID>.glb`・`public/assets/tex/<ID>.webp` に置き、目録（`data/assets.js`）に登録（`boneMap`・`clips`・`heightM`）。
4. 見本室（`gallery-rigs`）で表示を確かめ、スクリーンショットを撮る（正面・横・後ろ・動き）。白黒版も見る（07 §1.3）。

## 7. 素材発注書（依頼者用）

### 7.1 共通の約束
- 設定画は **Gemini または ChatGPT** で作り、1つの素材につき 3〜5 枚作って一番良いものを選ぶ。
- 3D化は **Meshy**（meshy.ai）の「Image to 3D」を基本にする（ほかのツールでもよい。GLB で書き出せること）。
  - 面の数は「少なめ（1万前後。小型の敵・小道具は5千前後）」、テクスチャはオン。
  - 人型は自動リグ（Humanoid）→ 動きを選ぶ → **GLB** で書き出す（動きを含める）。
- 無料プランで作った素材は利用条件が付く（例：CC BY 4.0）。その場合はタイトル画面の隅にクレジットを表示する（01 §5.3 に1行足す：「3D models: Meshy (CC BY 4.0)」）。
- できたファイルは、設計担当のチャットに添付するか、GitHub の `assets-raw/` にアップロードする。**ファイル名は §2 の ID** にする（例：`fuma.glb`、`tex_rock.png`）。

### 7.2 設定画の共通の書き方（キャラ・敵）
次の共通文の後に、§7.3 の「個別の文」をつなげて使う。

## 8. 受け入れ基準（A1 と取り込みの各回で使う）
1. 目録の全 ID について、ファイルが無い状態で起動 → コンソールエラー0、仮の見た目で表示、警告は ID ごとに1回。
2. 取り込んだモデル1体 → 描画命令＝2（輪郭込み。武器は別に2）。
3. 取り込んだモデル → 素材はトゥーン（07 §3.3）に置き換わり、`MeshStandardMaterial` が残っていない。
4. `npm run assets:check` → §5 の上限を超える素材が0（超えたら一覧を出して失敗）。
5. `boneMap` の左辺がすべて 07 §6.3 の骨名、右辺がファイル内に存在。
6. 技のクリップ伸縮：`hitS` が技の最初の判定フレームと ±1f で一致（`anim.test › hitAlign`）。
7. 白黒検査（07 §1.3）を取り込んだモデルでも満たす（明度の三層）。
8. 初回の読み込みの合計 ≤ 25 MB（`assets:check` が合計を出す）。

## 9. 依頼者が実機で確かめること
- 見本室「造形」で、取り込んだキャラが墨絵の画面になじんでいるか（浮いて見えないか）。
- 走り・攻撃の動きが自然か、手足が体にめり込んでいないか。
- 読み込みの待ち時間が気にならないか（タイトルの後）。
