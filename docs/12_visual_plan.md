# 12 見た目の作業方針（V5 以降）— 実装AIへの引き継ぎ

> 2026-11-16 作成。依頼者と合意済み。見た目の作業（`?scene=lookdev` と、その先の本編の見た目）は、この文書の進め方に従う。
> `PROGRESS.md` の「V4 以降への引き継ぎ」より、この文書を優先する。
> **2026-11-21 方針変更（依頼者）**：見た目は基本的に **Blender で作る**（12章）。1章の「外部素材は使わず、コードと three.js だけで作る」は取り消し。画像から3Dを作る有料の生成サービス（Tripo など）は使わない。

## 1. いまの位置（正直な評価）
- ゴールは「参考画像（`design-notes/lookdev/reference.png`）の水準の3Dゲーム」。外部素材は使わず、コードと three.js だけで作る（依頼者の方針。X には同じ条件で高品質な作例が多数ある）。
- 依頼者の目での評価：**現在は参考の約70%**。キャラクターと妖怪はそれより低い（実装AIの目で3〜4割）。
- V1〜V4 で報告していた「描き込み量 0.96」は**進み具合の指標として誤り**だった。画像を縮めて明暗の細かさを足しただけの数字で、太い線・紙の目・草の縁を「描き込み」に数えていた。今後この数字で進み具合を語らない（3章）。

## 2. 何が足りなかったか（V1〜V4 の反省）
1. **1つの物にかける手数**：数回の作業で30種類以上を一度に作った。主人公でも部品の表は数十行。
2. **近くで見て直す仕組み**：場面全体の画像で確認していたので、キャラクターは小さくしか写らず、粗さに気づけなかった。
3. **形を作る道具**：箱・円柱・球・回転体・管の組み合わせだけ。面取り・なめらかな細分・彫り込み・小部品の大量配置が無い。
4. **質感**：石・木・布・紙・毛皮に同じ模様2枚を貼っている。材質ごとの模様と凹凸の表現が無い。
5. **光**：明と陰の2色に近い。くぼみの暗がり・艶・濡れた照り返しが弱い。
6. **骨組み**：キャラクターは固まった形。ポーズと表情が作れない。

スマホ向けの制約（描画命令110以下、1体＝1メッシュ＋1素材）は理由にならない。部品をまとめて1つにすれば 1〜5 は全部できる。

## 3. 進め方の原則（これを変えない）
1. **1体ずつ作り込む**。場面全体を少しずつ直すことはしない。1体が合格するまで次へ進まない。
2. **合格を決めるのは依頼者の目**。実装AIは「工房」の拡大画像（4章）を参考と左右に並べて見せ、依頼者が合格・やり直しを言う。数字で合格にしない。
3. **毎回、拡大画像を自分で見てから報告する**。見ていない画像を「確認した」と書かない。
4. **参考画像が先**。主人公・妖怪・ボスは、依頼者が追加の参考画像（5章）を用意してから作る。届くまでは、参考画像が要らない作業（6章の道具と、今の参考画像に写っている物）を進める。
5. **数字の扱い**：`scripts/lookdev-shot.mjs` の「色の差・明るさの差」は色合わせの補助にだけ使う。「明暗の細かさ」（旧名：描き込み量）は参考値で、進み具合の根拠にしない。
6. 1回の作業（1セッション）の範囲は「道具1つ」または「1体の1巡」。広げない。

## 4. 工房（最初に作る。V5-0）
1体だけを大きく映して、回して見る画面。これが無いと作り込めない。
- URL：`?scene=lookdev&model=<形の名前>`（V5 第1回で実装済み。専用の場面は作らず lookdev に引数を足した）。
- 表示：無地の紙色の背景、台座、本編と同じ光・同じ水彩の仕上げ。指のドラッグで回転、2本指で拡大。
- 撮影：`node scripts/atelier-shot.mjs <形の名前> --ref=<参考画像>` で**決まった6視点**（実装済み。寄りの視点と動きの連続写真はまだ）（正面・背面・左・右・斜め上・顔や要所の寄り）を1枚の一覧にする。参考画像（5章のファイル）があれば左に並べる。出力は `tests/artifacts/atelier/`、依頼者に見せる版は `design-notes/lookdev/atelier/<名前>_vN.png`。
- 表示する数：三角形・描画命令（上限は 8章）。
- 動きの確認：待機・歩きなどを切り替えて、8コマの連続写真を作れること（V4 の `v4_yokai_motion.png` と同じ形式）。

## 5. 依頼者に用意してもらう参考画像
置き場所：`design-notes/lookdev/refs/`。ファイル名は `<名前>_<向き>.png`（例 `hero_front.png`）。
- 画風：`reference.png` と同じ水彩。**無地の明るい背景・全身・立ち姿**（武器は持たせるか、別の画像に）。
- 向き：**正面・真横・背面**の3枚が理想（最低でも正面と背面）。同じ人物・同じ服であること。
- あれば助かる：顔の寄り、武器だけの画像、手や履物の寄り。
- 作る順（優先の高い順）：①主人公（楓真）②提灯お化け（灯魂）③唐傘お化け（唐笠）④山犬（穢狗）⑤白雪・岩丈 ⑥面鬼 ⑦石凝神（ボス）。
- 大きさは長辺 1500px 以上。向きが多少ずれていてもよい（実装AIが読み取る）。
- 届いた画像は実装AIが必ず全部見て、色（パレット）と寸法（頭身・肩幅・武器の長さ）を `data/` に書き出してから作り始める。

## 7. 1体を作り込む手順（毎回これをなぞる）
1. 参考画像を全部見る。目立つ特徴を10個、箇条書きにして `PROGRESS.md` に書く（例：「袖は肘から先が広がり、袂が膝まで垂れる」）。
2. 大きな形（輪郭）だけを作る → 工房で6視点を撮り、**輪郭だけ**を参考と比べる。合うまで細部に入らない。
3. 中くらいの形（服の重なり、関節、顔の凹凸、武器の部品）。
4. 細部（彫り込み、小部品、ほつれ・欠け）。
5. 質感と色（参考画像から色を拾う）。
6. 動き（待機・歩き。妖怪は身じろぎとまばたき）。
7. 特徴10個を1つずつ「できた／まだ」で自己採点し、まだの物を直す。これを最低3巡。
8. 場面（`?scene=lookdev`）に戻して、遠目でも崩れないかを見る。スマホ相当（`--w=1000 --h=330 --dpr=3`）でも撮る。
9. 依頼者に「参考｜今回」の一覧を見せ、合格か、直す点を聞く。

## 11. つまずいた点の覚え書き（同じ失敗をしないために）
- GLSL の変数名に `patch` などの予約語を使うと、そのシェーダだけ真っ黒になる（エラーは console に出る。撮影スクリプトの出力を必ず読む）。
- 空は起動時に焼いた1枚の絵。細かすぎる模様は絵の解像度で潰れる。画面上で丸く見せたい模様は「方位と仰角」の座標で描く。
- 撮影の `--clip=x,y,w,h` は画面の座標（幅 1672 基準）。範囲を間違えやすいので、撮ったら必ず画像を開いて確かめる。幅 3000 を超える拡大撮影は時間切れになる。
- 数値の直書きは `tests/unit/literals.test.js` が落とす（小数と、絶対値3以上の整数）。調整値は `src/config/lookdev.js`、形と配置は `src/data/lookdev/` へ。
- 妖怪は形を自分の座標で作り、配置と動きはメッシュの行列で掛ける（`render/lookdev/yokaiMotion.js`）。動きは tick から計算する（時計を使わない）。
- 太い割れ目の模様を墨線にすると、大きな岩に太い黒線が出る。線にするのは細かい模様だけ。
- 依頼者は非エンジニア。報告は平易な日本語で短く。うまくいっていない点は先に正直に書く。

## 12. Blender で作る（2026-11-21〜）
- 道具：Blender（無料）を Python（bpy）で動かす。この作業環境では `python -m venv V && V/bin/pip install bpy`（npm の依存には足さない）。画面の機能（GPU）が無いので、描画・焼き込みは Cycles（CPU）。
- 共通の部品は `tools/blender/lib.py`。1つの形につき1つの台本（`tools/blender/<名前>.py`）を置き、いつでも作り直せるようにする。
- 流れ：①形（寸法は今の models.js の形に合わせる）②細かい形から三角形を減らした形へ、凹凸と陰を焼く ③位置・面の向き・部位から numpy で色と透明（破れ・穴）を描く ④1つの材質に色と凹凸の絵を貼って GLB ⑤glTF-Transform（`npx -y @gltf-transform/cli@4.1.1 webp`）で絵を WebP に圧縮 ⑥`public/assets/lookdev/` に置き、`data/lookdev/scene.js` の `glb` 表に登録する。
- ゲーム側：`render/lookdev/glb.js` が読み、塗りの材質（`MAP_TEX`：色の絵・凹凸の絵・透明）で描く。登録した名前は models の同じ名前より優先。小道具の配置・散らしは形ごとにインスタンス描画（描画命令は形ごとに本体＋影の2）。
- 上限は8章のまま（三角形・描画命令）。絵は小道具 512²、キャラ・妖怪 1024² を目安。
- 作る順（依頼者の選択 11/21）：小道具・背景（岩 → 大灯籠 → 注連縄の巨岩 → 石段と石垣）→ 妖怪 → 人物。
- 覚え書き：Blender の GLB の書き出しで接線（tangent）が入らないことがある → 読み込みで計算する。透明のある色の絵は JPEG にしない。Blender の絵に細部が入っているので、シェーダが足す線（割れ目・木目）は `procMul` で弱める。
